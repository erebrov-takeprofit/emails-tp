TakeProfit — Email Templates

Hand-coded, email-client-safe HTML for TakeProfit's transactional & notification emails. This page is a live index of the built templates, the design system guide, and the master content table.

📋 Notion — email table 📐 Design system guide 💻 GitHub repo

About this project

Each file below is one email template — pure table-based HTML with inline styles, built to render across Apple Mail, iOS, Gmail and Outlook (no flexbox/grid/JS). Images are served from AWS S3 (takeprofit-static.s3.eu-central-1.amazonaws.com), so this repo holds only HTML. Backend fills the {...} placeholders when sending.

The design system guide is the portable spec: tokens, components, footer variants, per-email subjects & preheaders. It's what keeps every email visually consistent.

How it works & how to update

Editing flow

  1. Draft & prompt in the Claude project “Email | Design, texts and coding rules” — the place for wording, subjects and coding rules.
  2. Edit the HTML in the git repo (one file per email). Filenames are kebab-case and mirror the email name.
  3. Log the change — add a dated entry to the Changelog below.
  4. Push to main → Netlify auto-deploys → the preview URLs update.
  5. Update the Notion table — subject, preheader, status, owner, variant, preview URL. Notion is the source of truth for metadata.

Single source of truth

  1. HTML + guide.md → this git repo (canonical).
  2. Email metadata (subjects, triggers, owners, statuses) → Notion table.
  3. Prompting / texts → Claude project. Point it at the repo rather than pasting a static copy, so it always reads the latest guide.

August 7, 2026Monthly digest flow documented (built in Customer.io, not here)▸
  • Wrote down the flow for the monthly “What’s New” digest in guide §14. It is deliberately not part of this repo: each issue is a copy of the previous month’s one-time send in Customer.io, so no digest HTML or Notion row belongs here.
  • Documented the three things the Customer.io copy endpoint silently drops and must be restored by hand — audience (filters comes back null), conversion goal, and the updates tag — plus the exact body shapes the API accepts.
  • Noted where digest assets deviate from §10 on purpose: 4× exports (cover 2400×680, body 2400×1360) at the bucket root, not 3× under emails/<name>/. Export from the email frame’s own image nodes — the separate “assets” frames are often stale or empty.
  • Link targets come from neither the copy doc nor Figma, so they are resolved via the TakeProfit docs MCP and verified with a real request. Newest features are usually still undocumented — those stay plain text with a TODO comment rather than a guessed URL.
  • Added a CLAUDE.md that routes to the right section per task, and a pointer in CONTRIBUTING.md.
August 4, 2026Figma → S3 → Customer.io asset pipeline▸
  • Images can now be exported from Figma and published to the takeprofit-static S3 bucket straight from Claude Code — no more manual download-and-upload round trip.
  • Added tools/upload-assets.py: it sets the public-read ACL, the Content-Type and a one-year Cache-Control, then verifies each URL with a real HTTPS request before printing it.
  • Documented the trap this exists for — the bucket has no bucket policy, so public read comes from a per-object ACL. A plain aws s3 cp uploads a file that answers 403 and silently breaks the image in the email.
  • Wrote down the retina rule (assets uploaded at 3×, HTML always states the logical size) and the new key layout emails/<email-name>/…; the bucket root stays legacy. See guide §10.1–10.2 and §11.1.
